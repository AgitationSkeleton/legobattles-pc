# The complete campaign table

All ninety missions, each with its internal class name, its map file, its world
and side, and its act and mission number. The full table is
[`docs/data/campaign_missions.tsv`](data/campaign_missions.tsv), regenerated by:

```powershell
python tools\lb_campaign.py --rtti out\eur\rtti.json ^
    --image out\eur\arm9\section_static_02000000.bin ^
    --lang out\eur\plain\LOC\UK_English.lng ^
    --overlay-map docs\data\overlay_missions.tsv --json out\eur\campaign.json
```

This supersedes `docs/06-overlays-are-missions.md`, which reproduced a
third-party table covering 64 of the 90. **All 90 are now recovered from the ROM
itself**, and the third-party table is retained only as an independent check —
which it passes: 64 of 64 of its map assignments agree.

## How it was derived

`Battles::CampaignMissionBase` has exactly 90 subclasses in the RTTI
(`docs/07`). Each mission's `.map` filename is stored in read-only data
immediately **after** that class's typeinfo and vtable — which is to say
immediately *before the next class's typeinfo*.

Getting that adjacency backwards is the natural mistake and it shifts the whole
table by one. The check that catches it: `CampaignMission1_CriminalMindsAct2`
must pair with `ma2_1`, mission 1 of act 2, and under the correct reading it
does. Under the wrong reading it pairs with `ma3_1`.

## The naming scheme, settled

Map files are `<world><side><act>_<mission>.map`:

| | world | | side |
| --- | --- | --- | --- |
| `c` | Castle | `k` | King |
| `p` | Pirates | `w` | Wizard |
| `m` | Space | `i` | Imperial |
| | | `p` | Pirate |
| | | `a` | Alien |
| | | `h` | Earth (human) |

`docs/06` left the side assignments marked unresolved rather than guessing. They
are now settled from the ROM's own text, and the guess that would have been
natural — that `mh` was the alien side, because "Search For Scum" reads as law
enforcement — was **wrong**:

- `mh1_1` "The Red Planet": *"Our Mars mission begins… Earth Command has dropped
  cargo pods full of supplies."* → **Earth**.
- `ma1_1` "Impact!": *"Ziff! Do I have to do everything myself? I get distracted
  for a few minutes and we crash on some ziffing rock!"* → **Alien**.
- `pp1_1` "Put to Sea": *"Ahoy Captain! I be gatherin' supplies to begin the
  search for the other pieces of yer treasure map."* → **Pirate**, so `pi` is
  Imperial, which its `pi1_1` "Royal Commission" corroborates.

The `Movies/` directory's six prefixes `A E I K P W` are the same six sides —
Alien, Earth, Imperial, King, Pirate, Wizard — four films each: `Intro`,
`Battle`, `Flavour`, `Outro`.

## Corroboration and the eight exceptions

The map filename encodes act and mission; so does the class name
(`CampaignMission<mission>_<Name>Act<act>`). Comparing the two independent
derivations: **82 of 90 agree**. The eight that do not, and what each one is:

| map | class | class says | assessment |
| --- | --- | --- | --- |
| `pp2_3` | `CampaignMission2_ProtectTheIslandersAct2` | act 2 #2 | **filename gap.** `pp2_2.map` does not exist. The classes number 1–5 consecutively while the files skip 2, so the four rows below it shift by one. Adjacency is right. |
| `pp2_4` | `CampaignMission3_HeadsUpAct2` | act 2 #3 | same |
| `pp2_5` | `CampaignMission4_PillagePlunderAndStealAct2` | act 2 #4 | same |
| `pp2_6` | `CampaignMission5_TheSetupAct2` | act 2 #5 | same |
| `pi3_5` | `CampaignMission6_AttackTheCoveAct3` | act 3 #6 | **adjacency confirmed independently.** The third-party table has `pi3_6` = "All Mine" and adjacency gives `pi3_6` = `CanYouDigIt` — both mining. `pi3_5` = "End Game" pairs with attacking the pirate cove, the Imperial campaign's finale. |
| `pi3_6` | `CampaignMission5_CanYouDigItAct3` | act 3 #5 | same |
| `cw2_1` | `CampaignMission2_GoodKnightAct2` | act 2 #2 | **unresolved.** A genuine pairwise swap with the row below, with no third source. |
| `cw2_2` | `CampaignMission1_TrollingAct2` | act 2 #1 | same |

So: 88 of 90 rows are corroborated or explained. The `cw2_1` / `cw2_2` pair is
recorded as **not corroborated** in the TSV's last column and should be settled
before anything depends on it.

Note the two campaigns use *different conventions* for a missing map. `ck1` has
no `ck1_5` and its classes number 1,2,3,4,6 — following the gap. `pp2` has no
`pp2_2` and its classes number 1,2,3,4,5 — ignoring the gap. That inconsistency
is in the game's own source, not in this derivation.

## Two loose ends worth chasing

**`pi3_4.map` exists and no mission class claims it.** The Pirates-Imperial
campaign has 16 map files for 15 missions. Every other campaign has exactly 15.
A cut mission is the obvious reading, and the map is there to be opened.

**The Wizard campaign has 16 mission text blocks for 15 maps.** In
`LOC/UK_English.lng`, campaign mission text is laid out one contiguous block per
mission, campaign by campaign, in sorted map order — a rule that holds for 45 of
45 missions across the `pi`, `mh` and `ma` campaigns, where the map assignment is
known independently. Applying it to the Wizard range (`ck3_4` "Confrontation"
ends at id 1521; `pp1_1` "Put to Sea" begins at 1838) yields sixteen blocks:

```
1528 Pieced Together      1657 Strength in Numbers   1795 Shoot The Messenger
1580 The Foundation       1730 A Devious Machine     1808 Homecoming
1596 Momentum             1740 Shrouded Garrison     1821 Swarm
1615 The Uninvited        1762 Search and Destroy    1831 Battle Royal
1634 Underfoot            1772 High and Dry
1644 Convenient Alliance  1785 Bring It Down
```

Sixteen titles, fifteen maps. Either one of these is not a mission title, or the
Wizard campaign also lost a mission. Not resolved here.

**A caution recorded because it nearly became a false conclusion.** Class short
names and displayed titles are *different name spaces*, and they collide.
`CampaignMission6_SwarmAct1` sits at `cw1_6` by adjacency while a mission
*titled* "Swarm" is the fourteenth block in the Wizard range. Reading the title
match as a positional match makes the two derivations look irreconcilable. They
are not — the game simply reuses words. Only 18 of 90 class short names match a
title verbatim at all; for the rest, `ck1_1` is class `RepairTheGarrison` and
title "Dark Shadows".
