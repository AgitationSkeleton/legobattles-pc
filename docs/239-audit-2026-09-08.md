# 239 — Full audit against the port's feature requirements

**Why this document exists:** an honest account of what is actually done, what
is done-but-unverified, and what is not done. Written as an audit only; **no
code was changed while producing it.**

**How to read the status column.** Three levels, kept strictly apart, because the
difference is where this project has repeatedly gone wrong:

* **MEASURED** — verified by a run whose evidence is quoted, with the instrument
  itself checked.
* **BUILT** — implemented and reasoned from the ROM, but its *effect* has not
  been observed in a live battle.
* **OPEN** — not done, or blocked, with the reason.

## Gameplay tuning: a stat observed moving, and moving back

Unit caps are the readable one. docs/58 and docs/68 place the allowance table at
`0x02126D94` as ten bytes indexed by build-limit class, shipped as
